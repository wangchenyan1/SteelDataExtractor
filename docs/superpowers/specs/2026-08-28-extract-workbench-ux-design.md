# 抽取工作台任务流与复核体验 · 设计规格

日期：2026-08-28  
范围：在现有 `steel_extract_tool_workspace` 上演进（方案 2：多视图工作台），不重写抽取引擎。  
前置规格：`2026-08-27-configurable-extract-tool-design.md`（配置模型、流水线、出处、解析、剪裁等仍有效；本文修正 UI 任务流、阶段可配、规则结果展示语义）。

## 1. 目标与非目标

### 1.1 目标

把当前偏「配置试跑 demo」的单页界面，改成同一人能当场完成真实抽取任务的工作台：

1. **项目** → **配置（字段 + 阶段 + 策略）** → **文献与运行** → **复核** → **导出**
2. 用户可在项目配置里**自定义性能抽取阶段**（数量、名称、每阶段字段），例如：骨架 + 力学 + 电导，或再加马氏体特征；不再表现为写死的「力学 / 磁学 / 图片过滤」四步。
3. 规则处理（性能来源、图片策略）的结果**仍出现在抽取结果树中**，用不同颜色方块标记，并显示原因；便于对照原文与图片复核。
4. 左侧原文：有 `source.pdf` 先看 PDF，否则看**渲染后的完整** `paper.md`（含插图）。
5. 右侧结果按层级展示（文章 → 样品 → 状态 → 性能 / 图片），相关图缩略图挂在对应样品/状态旁。

### 1.2 非目标（本轮不做）

- **标注**：不能改抽取值；不能把规则未通过项「恢复」为通过（恢复与改值属于标注，另开规格）。
- 任意实体骨架（自由增减 sample/condition 以外的层级关系）。
- 每次跑文献前临时改阶段（阶段只在配置时保存到项目）。
- 把四个只读快照项目迁到新 UI。
- 写回 `/internfs/wangchenyan/shougang/Extract_data`。
- 从导出文件一键导入覆盖另一项目。

### 1.3 与抽取 / 标注的边界

| | 抽取（本工具） | 标注（不做） |
| --- | --- | --- |
| 目的 | 调字段、阶段、策略，判断机器抽得对不对 | 产出人认定的正确答案 |
| 改值 | 否 | 是 |
| 规则未通过 | 异色展示 + 原因；可据此改策略或重抽 | 可改成通过并改值 |
| 动作 | 改配置、重跑阶段/字段、对照原文与图 | 编辑金标 |

## 2. 架构与导航

不重写 `pipeline` 核心调度；增加项目级阶段计划、结果 `status` 语义，并重做前端信息架构。

```text
项目
  → 配置（字段 + 抽取阶段 + 过滤策略）
  → 文献与运行（加 PDF / 选文献 / 按项目阶段跑）
  → 复核（左原文 · 右层级结果 · 图旁挂）
  → 导出（项目配置 或 抽取结果）
```

| 视图 | 职责 | 明确不做 |
| --- | --- | --- |
| 项目 | 选择 / 新建项目（模板 + 名称） | 不塞字段与 JSON 细节 |
| 配置 | 勾选字段、编辑阶段、白话配置策略 | 不跑抽取；主路径不展示 Schema/Prompt |
| 文献与运行 | 文献列表、解析、整篇/分阶段跑、重抽 | 不展示 `selected_field_ids` 等实现术语 |
| 复核 | 对照原文与层级结果；规则未通过异色 | 不能改值、不能恢复未通过项 |
| 导出 | 带走配置或结果 | 不写回 Extract_data |

主界面**不再**把「抽取步骤」四步清单和字段库实现细节作为常驻主角。运行时可用轻量进度展示当前阶段名（来自项目配置）。

## 3. 配置页

### 3.1 字段

- 按类别展示公共字段库：文章 / 样品 / 状态 / 性能 / 图片；使用中文 `label` 勾选。
- 可新增私有字段（本项目专用）。
- 编辑规则默认「仅本项目」；「写回公共库」放在高级操作，日常路径不露。
- 去掉与勾选重复的芯片双份 UI；不再在勾选区展示 `selected_field_ids` 等内部字段名。
- 每个已勾选的**性能**字段必须归属某个性能阶段；未挂阶段时保存配置须提示并拦截。

### 3.2 抽取阶段

- **骨架**固定为第一阶段：文章 + 样品 + 状态字段；不可删除、不可排到性能段之后。
- **性能阶段**由用户增删、改名、排序。示例：
  - 骨架 → 力学性能 → 电导性能
  - 骨架 → 力学性能 → 电导性能 → 马氏体特征
- 每个性能阶段包含：稳定 `id`、显示名、本阶段字段 id 列表（来自已勾选性能字段）。
- **默认生成**：按字段当前 `group`（或模板 `property_groups`）生成初稿；用户可合并、拆分、改名、新增空段再填字段。
- **图片**：图片类字段仍可勾选；图片元数据仍在骨架步由模型填写（钢铁模板行为不变）。**不**再生成名为「图片过滤」的用户可见抽取阶段。
- 落盘：写入项目覆盖层的阶段计划（可读的 steps / stage 列表）。运行时 `get_steps`（或等价合成）**以该计划为准**，不再假定模板只有力学/磁学两组且界面写死四步。
- 模板上的 `property_groups` 仅作默认分组与字段库默认 `group` 的参考，不限制项目只能有这两段。

### 3.3 过滤策略（白话）

| 策略 | 用户可见说明 | 对结果的影响 |
| --- | --- | --- |
| 性能来源 | 摘要目标值、宣传区间等不算可靠测量 | 结果中保留，`status=rejected_by_rule`，异色 + 原因；无「恢复」 |
| 图片策略 | 如只关注组织形貌；XRD/曲线等标为未通过 | 同上 |

策略参数仍可存在于覆盖层（现有 `property_source` / `figure_filter` 结构可复用），但配置 UI 必须用白话说明用途，并允许在配置页编辑，不得只藏在手改 JSON。

高级选项（文献与运行）：`single_pass` 对照——不做策略标记（或全部视为通过），便于对比优化前后。

### 3.4 配置生效时机

- 保存后只影响**下一次**抽取或重抽。
- 不改写已有 run。
- 改阶段或字段后提示：「需重新抽取后结果才按新配置」。

## 4. 文献与运行

- 文献列表：本项目 `paper_id`；支持上传 PDF（→ `paper.md` + `images_from_md` + `source.pdf`）或选择已有解析结果。
- 主操作：按项目阶段整篇一次跑完；或按阶段逐步跑。进度文案使用配置中的阶段显示名。
- 次要操作：只解析、只重抽某字段（当前文献或本项目已抽文献）。
- 骨架未完成时性能阶段不可用；重跑骨架作废下游并重跑（沿用 2026-08-27）。
- 跑完后可一键进入该篇复核。

## 5. 复核

### 5.1 左侧原文

- 存在 `source.pdf` → 默认以 PDF 展示。
- 否则 → 渲染完整 `paper.md`（Markdown + 文中图片），**禁止**仅用未渲染的 `<pre>` 文本冒充「完整解析结果」。
- 点击右侧带 `excerpt` 的字段：若当前为 PDF，切换到文本视图并做出处高亮；未命中则在字段旁展示摘录与 `location`。
- 落盘 `paper.md` 始终完整；送入模型的剪裁文本可另存；复核左侧不展示「剪裁后文本」作为默认（排查需要时可后续加页签，本轮非必须）。

### 5.2 右侧层级结果

按结构展示，使用中文标签与样品/状态 id，不暴露 `samples[0].mechanical_properties.yield_strength` 作为主文案：

```text
文章信息
样品 S1 …
  状态 C1 …
    性能字段…
    （相关图缩略图）
  状态 C2 …
图片（按图列出）
```

字段块内容：中文名、值、单位、位置、摘录状态（已定位 / 仅摘录 / 无摘录）。

### 5.3 规则未通过的展示与数据形状

- 性能来源未通过、图片策略未通过的项**留在结果树同一位置**，方块颜色不同（如琥珀/灰），并显示简短原因。
- **无**改值入口；**无**「恢复为通过」按钮。
- 合并写入 `paper.json` 时，事实对象增加（或等价）：

```json
{
  "value": "600",
  "unit": "MPa",
  "source": "abstract_target",
  "excerpt": "yield strength above 600 MPa",
  "location": "Abstract",
  "status": "rejected_by_rule",
  "reject_reason": "摘要目标值 / 来源不可靠"
}
```

- `status` 取值：`accepted`（默认通过）| `rejected_by_rule`。校验阶段不得丢弃这些对象，也不得只删进 warnings 角落而不进结果树。
- `review_notes` 仍可保留明细列表，与树节点互为索引。
- 复核默认展示全部；可筛选「仅未通过」。

### 5.4 相关图片

- 通过 `sample_id` / `condition_id` / `placeholder_index` 将图挂到对应样品或状态旁，显示缩略图。
- 点击放大；资源来自解析目录 `images_from_md/`（需提供静态或 API 取图）。
- 策略未通过的图同样显示缩略图，样式为未通过。

### 5.5 复核页不做

- 内联编辑值  
- Schema / Prompt / 只读快照表堆在主路径  
- 将「图片过滤」展示为抽取步骤  

## 6. 导出

| 导出物 | 内容 | 用途 |
| --- | --- | --- |
| 项目配置 | 生效字段 + **阶段计划** + 策略 + Schema（扩展现有 export） | 同事带走配置 |
| 抽取结果 | 本篇或本项目已抽文献；可选「仅 `accepted`」或「含 `rejected_by_rule`」 | 带走数据 |

## 7. 错误处理

沿用 2026-08-27 第 7 节，并增量：

| 情况 | 处理 |
| --- | --- |
| 无 source.pdf 且无 paper.md | 复核左栏提示先解析 |
| paper.md 引用图但文件缺失 | 缩略图失败态，不阻断其它字段 |
| 摘录无法匹配 | 「仅摘录」，非抽取失败 |
| 规则未通过 | 结果树 + status，异色；默认不进「仅 accepted」导出 |
| 某性能阶段失败 | 其它阶段保留；可重试 |
| 空性能阶段或性能字段未挂阶段 | 配置保存时拦截 |
| 性能来源/图片策略命中 | **不再**从结果中删除；改为 `rejected_by_rule` |

## 8. 数据与 API 增量

### 8.1 覆盖层

在 `configs/projects/<id>.json`（或合成 steps 的等价结构）中，阶段计划为项目真相来源。可继续用 `steps` 数组表达，例如：

```json
{
  "steps": [
    {"id": "entity", "type": "entity", "name": "骨架"},
    {"id": "mechanical", "type": "property", "name": "力学性能", "group": "mechanical_properties", "fields": ["yield_strength", "tensile_strength", "elongation"]},
    {"id": "conductivity", "type": "property", "name": "电导性能", "group": "conductivity_properties", "fields": ["electrical_conductivity"]}
  ]
}
```

- 配置 UI 编辑并保存的阶段计划写入覆盖层的 **`steps` 数组**，作为运行时唯一真相；不再同时维护一份易漂移的 `step_overrides`（若旧字段存在，加载时以 `steps` 为准并在下次保存时收敛）。
- `property_source` / `figure_filter` 仍在覆盖层，由策略 UI 读写。

### 8.2 流水线

- `validate_properties` / `classify_figures`：默认模式改为**标记而非删除**；`single_pass` 不做策略标记。
- 合并结果中的性能与图片均带 `status`（缺省视为 `accepted` 以兼容旧数据）。
- 图片策略步骤可仍作为内部后处理运行，但**不**作为用户阶段列表中的一步。

### 8.3 HTTP

在现有 API 上扩展（名称可微调，语义固定）：

- 覆盖层读写已含阶段计划与策略。
- `GET` 解析资源：paper.md 渲染所需的图片（如 `/api/papers/:id/images/...` 或静态映射到 `images_from_md`）。
- `GET` PDF：`source.pdf` 供 iframe。
- 结果 API 返回完整树（含 `rejected_by_rule`），另可带 warnings 索引。
- 导出：配置导出含阶段；新增结果导出查询参数 `include_rejected=true|false`。

## 9. 验收

1. **导航**：五视图可切换；复核与运行主路径不出现字段库实现术语，不出现写死的「力学 / 磁学 / 图片过滤」四步清单作为唯一阶段模型。
2. **阶段**：可将项目配置为「骨架 + 力学性能 + 电导性能」（无磁学段）；运行进度与配置阶段名一致；未挂阶段的性能字段无法保存配置。
3. **策略展示**：`demo_steel` 中摘要目标屈服强度与 XRD 图出现在结果树中且异色，原因可读；无「恢复」按钮；`paper.json` 含 `status=rejected_by_rule`。
4. **原文**：有 `source.pdf` 显示 PDF；否则渲染 md（可见插图），非纯文本预览。
5. **层级 + 图**：结果按样品/状态展开；相关缩略图出现在对应节点旁。
6. **导出**：配置导出含阶段计划；结果导出可选仅 `accepted`。
7. **回归**：出处高亮、骨架依赖与失效、单字段重抽、离线 `demo_steel` mock 仍可用；不写回 Extract_data。

## 10. 实现顺序

1. 多视图导航骨架（空壳切换）
2. 配置：字段简化 UI + 阶段编辑 + 策略白话编辑
3. 流水线：阶段读项目计划；校验改为标记 status
4. 复核：PDF / 渲染 md、层级结果、异色、缩略图与取图 API
5. 导出扩展与验收用例

## 11. 现有代码演进要点

- `app/`：拆为多视图；删除复核主路径上的双份字段芯片、实现术语、写死步骤观感；新增阶段编辑与策略表单。
- `tools/pipeline.py`：`validate_properties` / `classify_figures` 改为标记；合并保留 rejected；步骤以覆盖层阶段计划为准。
- `tools/config_model.py`：阶段保存/校验（骨架第一、性能字段均需归属阶段）；模板 `property_groups` 仅默认。
- `tools/workbench_server.py`：PDF/图片资源路由；结果与导出参数。
- 文档：本规格修正 2026-08-27 中「剔除出最终结果、仅进 review 列表」及「图片过滤作为步骤」的表述；实现与验收以本文为准。
