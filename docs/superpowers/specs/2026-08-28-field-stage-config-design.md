# 配置页：字段勾选自动挂阶段 · 设计规格

日期：2026-08-28  
范围：工作台真实任务补齐的**第一块**——配置页「选字段 / 看阶段 / 保存」。不重写抽取引擎。  
总目标（三块都做，按序落地）：① 本文件（字段勾选自动挂阶段）② 文献上传 / 队列 / 批量跑 ③ 字段库补齐（电导、硬度等）与新增字段体验。  
前置规格：`2026-08-28-extract-workbench-ux-design.md`（五视图、阶段可配、策略标记仍有效）。本文修正其中配置页的**双份勾选**、**勾选即时保存**，以及空阶段保存规则。

## 1. 目标与非目标

### 1.1 本块目标

配置页上「勾选」是唯一的「抽不抽」入口；性能字段勾上后自动进入对应抽取阶段。阶段区只展示已挂字段，用于改名、排序、把字段改到另一段。勾选与改阶段都先留在页面草稿，只有「保存配置」才写入项目。

成功标准：同一性能字段不必勾两次；文章/样品勾选不再单独即时 PUT；保存前未落盘的改动刷新即复原。

文献上传、批量跑、补字段**是同一产品的目标**，在后续规格中写，不在本文件展开。

### 1.2 本块不做（不是产品放弃）

- 本文件不规定文献上传、队列、批量跑的交互（见后续「文献」规格）
- 本文件不往字段库加电导 / 硬度（见后续「字段库」规格）
- 策略表单改文案、复核 / 导出改版、pipeline / prompt
- 未保存草稿的横幅、恢复、跨会话暂存
- 任意实体骨架（sample / condition 层级仍由模板固定）

### 1.3 与 2026-08-28 UX 规格的关系

| 原文 | 本文 |
| --- | --- |
| 性能字段须挂阶段，阶段编辑器里再勾一遍字段 | 勾选即挂段；阶段区是芯片名单，不是第二套勾选 |
| 未写明勾选是否即时保存 | 勾选 / 改阶段 / 改策略一律进草稿，仅「保存配置」写入 |
| 空性能阶段保存时拦截 | 保存时丢掉空段，不报错 |
| 「写回公共库」放高级 | 不变；规则弹窗行为本轮不改 |

运行时仍以覆盖层 `steps` 为阶段真相；模板 `property_groups` 只作默认组名与 `group` 参考。

## 2. 页面结构

配置页从上到下：

1. **字段配置**：按文章 / 样品 / 状态 / 性能 / 图片勾选；已勾选旁可点「规则」；可新增私有字段。
2. **抽取阶段**：骨架固定第一段（不可删、不可后移）；性能阶段卡片：显示名、已挂字段芯片、上移 / 下移 / 删除、「添加性能阶段」。
3. **过滤策略**：保持现有表单，随「保存配置」一起写入。
4. **保存配置**：唯一把草稿写入覆盖层的主按钮。

模型接口、字段数量卡片不参与本规格逻辑，本轮不验收是否隐藏。

阶段区**禁止**再渲染「所有已选性能字段」的 checkbox。字段芯片只表示「已挂在这一段」。把字段改到另一段：首选把芯片拖到目标段；等价实现是芯片上的「移至」菜单。两者都算验收通过，语义相同。

## 3. 自动挂段

骨架不由勾选生成。文章 / 样品 / 状态 / 图片的勾选只决定骨架步（及图片元数据）抽哪些字段。只有 `category=property` 的字段改变性能阶段列表。

### 3.1 锁定字段

下列字段在界面上勾选且禁用取消；保存时若缺失则补回已选集合：

- `sample_id`（样品编号）
- `condition_id`（状态编号）
- `figure_id`（图号）
- `placeholder_index`（占位索引）

字段库里没有的锁定 id 不强制插入。

### 3.2 勾上一个性能字段

在草稿上执行，不请求网络：

1. 取该字段的 `group`（库字段或私有字段上的值）。
2. 目标段 = 草稿中第一个 `type=property` 且满足任一条件的段：
   - 该段的 `group` 等于字段 `group`（两者都非空），或
   - 该段已挂的某个字段与当前字段同 `group`（`group` 均非空）。
3. 找不到目标段则新建一段：
   - `id`：模板组 id 去掉后缀 `_properties`（如 `mechanical_properties` → `mechanical`）；若该 id 已被占用则加后缀保证唯一。
   - `name`：先查项目覆盖层 `property_groups`，再查模板 `property_groups`（如「力学性能」）；都没有则用 `group`。
   - `group`：字段的 `group`。
   - 无私有/`group` 为空：进入或新建 `id=other`、`name=其他性能`、`group=other_properties`。
   - 项目自建大类见 `2026-08-28-field-library-groups-design.md` 第 3 节；本块只负责按 `group` 挂段，不负责增大类。
4. 把字段 id 追加到目标段 `fields`（已在则不动）。
5. **不**重排、**不**改名已有阶段，**不**把已经挂在其他段的同组字段拽回。

### 3.3 取消勾选

从所有性能段的 `fields` 中移除该 id。某一段 `fields` 变为空则从草稿删掉该段。

非性能字段的取消只改已选集合，不影响阶段。

### 3.4 人改阶段

| 动作 | 结果 |
| --- | --- |
| 改名、上移、下移 | 只动该段；不改勾选 |
| 字段改到另一段 | 只改归属；上面勾选仍为已选 |
| 添加性能阶段 | 草稿增加空段；保存时若仍空则丢掉 |
| 删除一段 | 其中字段变为「已勾选但未挂」；保存前必须改挂到某段或取消勾选 |

删除段后的未挂字段在阶段区下方用中文名列出，不静默取消勾选。

### 3.5 打开已有项目

草稿 = 覆盖层的 `selected_field_ids` ∪ `steps` ∪ 策略。

- 已有非空 `steps`：**不要**按 `group` 重生成（保留已改的段名、顺序、跨组挂载）。
- 有已选性能字段、但没有 `type=property` 的段（含 `steps` 缺失或只有骨架）：按第 3.2 节对每个已选性能字段走一遍挂段，得到初稿。只在**从服务器载入覆盖层**时做一次（打开项目、刷新、保存成功后），不要在每次切回配置页时重算。

### 3.6 新建项目

`create_project` 在创建当时写入：

- `selected_field_ids`（调用方勾选；并补上第 3.1 节锁定字段，若库中存在）
- `steps`：`generate_steps(template, effective_fields, overlay)` 的结果（骨架 + 按 group 的性能段）

创建本身是一次落盘。之后在配置页上的改动重新走草稿 →「保存配置」。

## 4. 草稿、保存、校验

### 4.1 草稿范围

进入配置视图时从覆盖层拷贝：

- 已选字段 id
- 阶段 `steps`（按第 3.5 节补初稿）
- 策略表单（`property_source` / `figure_filter`）

此后勾选、挂段、改段名、改策略**只改这份草稿**，不发 PUT。  
规则弹窗（仅本项目 / 写回库）保持现有即时写入，不纳入本轮草稿。

切换项目或刷新：丢弃未保存草稿，重新 GET 覆盖层。切到「文献 / 复核 / 导出」再回到配置、且未换项目时，内存草稿保留，不得在 `setView("config")` 时用服务器数据盖掉未保存改动。不做横幅、不做恢复。

### 4.2 保存顺序

「保存配置」一次处理：

1. 从草稿 `steps` 中去掉 `type=property` 且 `fields` 为空的段。
2. 把第 3.1 节锁定字段并入已选。
3. 若仍有已选性能字段未出现在任一性能段 → 拦截，文案用中文 `label` 列出（无 label 时用 id），不写盘。
4. `PUT /api/projects/:id/config`，body 为完整覆盖层，至少包含：`selected_field_ids`、`steps`（骨架第一 + 剩余性能段）、`property_source`、`figure_filter`，以及原有的 `template_id` / `private_fields` / `field_overrides` 等未改键。
5. 成功：用服务器数据替换草稿；提示「配置已保存。需重新抽取后结果才按新配置。」不改已有 run。
6. 失败：草稿保留，显示错误，不假装已保存。

无性能字段也可以保存：`steps` 仅含骨架。

无覆盖层的项目：不提供勾选即时写入；保存仍提示无法保存（与现网一致）。

### 4.3 后端校验 `validate_overlay_stages`

与 4.2 对齐，在现有「骨架第一且唯一、禁止 `type=figure`、字段不重复、不得挂非性能 id」之外：

- **先**删除空性能段，再校验；空段不再抛「fields 不能为空」。
- 未挂的已选性能字段仍报错。
- `save_overlay` 在校验前做同样的空段剥离，写入磁盘的 `steps` 不含空性能段。

## 5. 组件与数据流

| 单元 | 职责 | 依赖 |
| --- | --- | --- |
| 字段库勾选（`app.js`） | 改草稿已选；性能字段调用挂段；锁定项禁用 | 字段库、阶段草稿 |
| 阶段预览 | 芯片 + 改名/排序/改挂/加段/删段 | 阶段草稿 |
| 挂段函数 | 实现 3.2 | 字段 `group`、模板 `property_groups` |
| 保存配置 | 实现 4.2 | `PUT .../config` |
| `create_project` | 实现 3.6 | `generate_steps` |
| `validate_overlay_stages` / `save_overlay` | 实现 4.3 | 覆盖层 + effective fields |

运行时 `load_field_config` / `get_steps` 继续读覆盖层 `steps`，不为「自动挂段」增加新步骤类型。

```text
打开配置 → GET 覆盖层 + 字段库 → 草稿（必要时按 3.5 补段）
勾选/改挂/改名 → 只改草稿
保存 → 4.2 → PUT → 草稿与磁盘对齐
```

## 6. 错误处理

| 情况 | 处理 |
| --- | --- |
| 保存接口失败 | 草稿保留，显示错误 |
| 打开配置无覆盖层 | 提示无法保存 |
| 已勾选未挂阶段 | 保存拦截，中文名列表 |
| 空性能阶段 | 保存时丢掉，不报错 |
| 锁定字段被异常去掉 | 保存时补回 |
| 拖拽/改挂到已含该字段的段 | 忽略（id 不重复） |

## 7. 验收

1. 勾「屈服强度」：阶段区出现「力学性能」及该字段芯片，无第二套性能勾选。不点保存则刷新后勾选与阶段均复原。
2. 再勾「抗拉强度」：进入同一「力学性能」段，不新建第二段。
3. 取消该段最后一个已选性能字段：该段从草稿消失。
4. 将字段改挂到自建/已改名段后，再勾同 `group` 字段：进入已改名的那段，不重生成默认段。
5. 未挂字段时保存失败并列出中文名；仅有空段时保存成功且磁盘 `steps` 无空段。
6. `样品编号` / `状态编号` / `图号` / `占位索引`（库中存在时）不能取消。
7. 新建项目：落盘 JSON 含按勾选生成的 `steps`；打开 `demo_steel` 不重算已保存的段名与顺序。
8. 回归：保存后的 `steps` 仍可供整篇抽取；文献页、复核、策略语义不作为本轮功能改动。

## 8. 测试

- `tests/test_config_stages.py`：空段被剥离后可通过校验；未挂字段仍失败；`create_project` 写出非空 `steps`（在勾了性能字段时）。
- 前端或 API 级：勾选不单独 PUT；「保存配置」才 PUT。阶段 DOM 不含「所有性能字段」checkbox。
- 现有阶段 / 覆盖层用例按 4.3 改断言，不再期望空段报错。
